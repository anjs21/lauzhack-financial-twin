# FAQ — Technology and Architecture

**LauzHack 2026 | AI Financial Twin**

### 1. Is there a mandatory programming language?
No. Python, JavaScript, C#, Rust, Julia, R, or other languages are possible.

### 2. Must we use an LLM?
No. LLMs are optional. If used, verify calculations with a suitable computational model.

### 3. Can we run AI models locally?
Yes. Free tools such as Ollama and llama.cpp can support local inference, subject to model licenses and hardware limits.

### 4. Can we build a serious game?
Yes. Godot, Phaser, and other game engines are options. Game events should update financial state correctly.

### 5. Can we use Unity or Unreal Engine?
Potentially, subject to their current license and usage terms. They should not be described as universally open-source or unrestricted.

### 6. Can we use reinforcement learning?
Yes. Define states, actions, transitions, rewards, and constraints. Benchmark against a simpler baseline.

### 7. Can we use multi-agent systems?
Yes. Explain agent roles, interactions, and how the financial accounting remains consistent.

### 8. Can we use Monte Carlo?
Yes, optionally, to explore uncertainty under stated distributions. Monte Carlo does not make the Financial Twin a forecasting product.

### 9. Can we use causal inference?
Yes. State causal assumptions clearly; observed correlations alone do not establish intervention effects.

### 10. Can we use optimization?
Yes. Disclose objective functions, constraints, and trade-offs; a mathematically optimal result is not automatically the best life choice.

### 11. Can we experiment with quantum computing?
Yes. Simulators and hybrid quantum-classical methods are possible. Do not claim quantum advantage without a credible classical comparison.

### 12. Can we create AR/VR or 3D experiences?
Yes. Ensure the immersive interface reflects real calculations and remains understandable.

### 13. Can we build with no cloud services?
Yes. Local applications and offline demonstrations are possible.

### 14. Are all listed tools completely free?
Many are free to install or open-source, but hosted inference, cloud compute, hardware, model weights, or assets may have costs or restrictions.

### 15. Can we combine multiple architectures?
Yes. For example, an LLM interface + deterministic financial engine + scenario optimizer + game visualization.

### 16. Is a sophisticated stack automatically better?
No. Judges should consider what is demonstrated: correctness, meaningful scenario exploration, technical quality, explainability, and user value.

### 17. Where are the technology links?
See `resources/technology/` for optional frameworks, source repositories, and installation resources.
